# 決定事項の総覧

作成: 2026-09-21 / 各設計ドキュメントに分散した決定を一箇所に集めたもの
未決事項は[未決事項の一覧](open-issues.md)を参照

## 0. 繰り返し現れた原則

個々の判断より、**同じ原則が何度も適用されている**ことのほうが重要である。新しい判断に迷ったら、まずこれらに当てる。

| # | 原則 | 適用された場面 |
|:--:|---|---|
| P1 | **計算で出せるものはファイルに書かない** | 図のレイアウト座標／画面の並び（入れ物）／コメントの現在位置／図表番号／目次・図表一覧 |
| P2 | **既定は自動、人が触ったところだけ疎に記録する** | 図のピン留め／表の罫線・塗りつぶし／ページ制御 |
| P3 | **語彙を、出力先が表現できる範囲に制限する** | 図形は DrawingML プリセット／色は直値禁止でトークンのみ／フォントは同梱品のみ |
| P4 | **定着した記法を借りる。発明しない** | `@import`（MPE）／flowchart 記法（Mermaid）／`---`（Marp） |
| P5 | **専用ツールが明確に優れている領域には手を出さない** | ER 図 → ErCreator／シーケンス図 → Mermaid |
| P6 | **黙って捨てない** | アンカーを失ったコメント／フォントに無い字／読み戻せなかった図形 |
| P7 | **人間可読と機械可読は対立しない** | 両方を殺すのは「機械生成の不透明な構造」。両方を活かすのは「構造を持った整形済みテキスト」 |
| P8 | **設定にせず、固定する** | 意味トークン 4 種／図表の採番方式／テーマの二重化を認めない |

## 2. ファイル形式と記法

| 決定 | 出典 |
|---|---|
| 地は **Markdown**。特殊要素が**埋め込みオブジェクトとして浮く**。`.ipynb` のような JSON は採らない | [編集 UI](editor-model.md) |
| 特殊要素は Markdown に直書きせず**外部ファイル**（`.dgm` / `.table`）に分ける | 同上 |
| インラインの境界は**「専用エディタが要るか」**。単純な表は直書き、結合セルを持つ表はファイル | [表モデル](table-model.md) |
| パスが**共有物かどうか**を表す（`docs/<文書名>/` はその文書専用、`shared/` は共有） | [編集 UI](editor-model.md) |
| 参照記法は **`@import "path" {attr}`**（MPE 互換）。読み取り時は `![alt](path){attr}` も受理 | [参照記法](reference-syntax.md) |
| 種別は**拡張子**で決める | 同上 |
| **区切りは `---`**（Marp 互換）。PDF では改ページ、PPTX ではスライド分割、編集 UI ではシートの区切り。**水平線ではない** | [出力モデル](output-model.md) / [シートモデル](sheet-model.md) |
| **HTML でもシート境界で強制改ページする**（当初の「HTML は連続表示なので切らない」を改めた） | [シートモデル](sheet-model.md) |
| **本文の改行は、出力でも改行にする**（設計書は意図して短い行で書く） | 実装時に決定 |
| 太字・斜体・コードは **Markdown の記法そのまま** | [文字書式](inline-format.md) |
| **文字色・塗りつぶしは書いた人が色を選ぶ。意味トークンの語彙は撤回した**（2026-09-26）。語彙の中心だった `changed` が、そもそも人の書くべき情報ではなかったため | [文字書式 §2.1](inline-format.md) |
| 記法は **Pandoc の `[文字列]{color=#rrggbb}`**。**`#abc` / `#aabbcc` 以外は span にしない**（任意の CSS を通さない） | 同上 |
| **既存の `{.changed}` などは読み続ける**（新しく書く手段としては提供しない） | 同上 |
| **図表番号は自動採番。ファイルに書かない。** 採番は**文書単位**で、図・表は**通し番号**（章番号を含めない） | [参照記法](reference-syntax.md) |
| 見出しは**階層番号**（図表とは別体系） | 同上 |
| **番号を本文や要素の中に直接書いてはならない。** ラベルで参照する（`@fig-…` / `@tbl-…` / `@sec-…`） | 同上 |

## 3. 作図（`.dgm`）

| 決定 | 出典 |
|---|---|
| **3 層モデル**（意味 / レイアウト / スタイル）。正本は 1 ファイル・セクション分割 | [作図モデル](diagram-model.md) |
| **自由配置型が基盤**、グラフ型はその上の特殊化。違いは **L2 をどれだけ埋めるか**だけ | 同上 |
| 図形語彙は **DrawingML のプリセットに限定**。超える表現はラスタへフォールバックし警告 | 同上 |
| 自動レイアウトは **TALA**（2026-09 に MPL-2.0 で OSS 化） | 同上 |
| **ER 図は ErCreator（`.ermlx`）、シーケンス図は Mermaid に恒久的に委譲** | 同上 |
| **グラフ型の編集はキーボードだけで完結させる。** マウスは例外処理用。L1 記法は Mermaid の flowchart に寄せる | 同上 |
| スタイルトークンは**表と共通**にし、凡例を文書単位で一つにまとめる | 同上 |
| セクションは **`free` / `flow` / `overlay` / `layout` / `style`**。`overlay` は画像への注釈（座標と文言だけがテキストとして差分に載る） | [作図モデル](diagram-model.md) |
| **ピン留め座標と自動配置座標は同じ座標系**（原点は左上）。別系だとピンが図の外へ飛ぶ | 実装時に判明 |
| **同梱の自動レイアウトは階層配置**（最長経路で段を決め、逆流辺を外し、重心法で並べる）。決定性があることを優先する。TALA は将来の差し替え候補として残す | 同上 |
| 接続線は**素直な直線を第一候補**とし、図形を貫くなら**脇の通路**、それも塞がっていれば**図の外周を回る** | 同上 |
| コードブロックは**言語名で色を付ける**（highlight.js）。色はクラス名で出し、テーマが決める。PDF はブラウザが解決した色を読むので、そのまま載る | 2026-10 |
| **Mermaid は本文のコードブロック（` ```mermaid `）と `.mmd` の両方で描く。** 見せ方（図 / コード / 両方）は**ブロックごとにファイルへ書く**（`{view="code"}`）。読む人の切り替えではなく著者の指定なので、HTML・PDF・PPTX も同じものを出す。VS Code の画面の切り替えボタンは、この属性を書き換える | 2026-10 |
| Mermaid の描画にはブラウザが要る。**書き出した HTML は描画のスクリプトを内蔵する**（gzip で圧縮し、開いたときに展開。外へは取りに行かない）。PDF では描いた図を**画像にして**載せる（PDF の描画器は Mermaid の矢印に使われる SVG の marker を追えない）。PPTX でも画像。Mermaid には PowerPoint に渡せる図形が無いので、`.dgm` と違って編集はできない | 2026-10 |
| コードブロックの上に**言語名を出す**（HTML・PDF にも出る。読み手にも要る情報なので編集画面の飾りにしない）。DocPresenter の画面では、その横に**全文のコピー**ボタンを置く（こちらは画面の飾り） | 2026-10 |
| PDF の**表紙は 1 ページを使い切る**。題名を上寄りに大きく、文書の事実（番号・版・状態・作成・更新）を下に表で置き、ページ番号は印字しない（数には入れる）。**目次は次のページから**。画面では表紙を作らない。PDF の組版がページに付ける `dp-paged` の印でテーマが切り替える | 2026-10 |
| VS Code で `output:` を持つ文書を**まとめて書き出す**コマンドを 2 つ置く。各文書の指定どおりに書くものと、形式を選んで書くもの。PDF の組版は、そのとき開く「DocPresenter 書き出し」の画面がする | 2026-10 |
| `.dgm` も **DocPresenter で開ける**（エクスプローラーの右クリック）。図だけを取り込む 1 行の文書として、文書と同じエディタで見せる。書き換えるのはその `.dgm` だけ | 2026-10 |
| VS Code に**書き出しのボタン**（HTML / PDF / PPTX）を置く。開いている文書を、押した形式で書く。PDF の組版はその文書の WebView がし、PDF はこの PC のフォントで拡張機能が書く | 2026-10 |
| `flow` の接続線は**上下左右にだけ伸ばし、角を丸めて描く**（段の間の真ん中で横に折れる）。斜めの線は、行で読む設計書に 3 つ目の向きを持ち込む。丸めるのは描画だけで、ファイルに残るのは今まで通り角の点。`free` は直線のまま。PPTX では**カギ線コネクタ**にして両端を図形に付ける（角は丸まらないが、PowerPoint で図形を動かしても線が付いてくる） | 2026-10 |
| 接続線のラベルが重なったら、**その線上をずらす**（横へ逃がすとどの線のラベルか分からなくなる） | 同上 |
| 矢印は `marker` ではなく**多角形として描く**。1 ページに複数の図が載るので `id` を使えない | 同上 |
| **画面設計も `free` で描く。** 専用の形式は作らない。実装前は作図、実装後は `overlay` で画像に注釈 | [画面設計](screen-design.md) |
| **`"…"` は枠線のない文字**（`text` 図形）。画面はほとんどが「何かの上に載った文字」 | 同上 |
| 図形の色も**直値**（`fill` / `line` / `color`）。**文字の寄せ** `align` を加えた。中央揃えだけの画面は画面に見えない | 同上 |
| **レイアウト層に「入れ物」を加えた**（`stack` / `grid`）。ピンだけの層は、同じ事実（間隔・向き・幅）を座標の数だけ複製していた。1 行足した変更が 6 行の差分になるのは **P1** に反する | [作図モデル L2](diagram-model.md) / [画面設計 §3.7](screen-design.md) |
| **入れ子は構文ではなく名前で繋ぐ。** 入れ物の中に入れ物を書かない。XAML が読めなくなるのは記号の数ではなく深さのせいなので、**どの画面でもブロックの深さは 1** に保つ | 同上 |
| **セルの記法は `grid-template-areas` から借りる。** 区切りは `;`、空きは `.`、またぐときは同じ名前を並べる。表の罫線記法（`\|` と `^`）とは別にする——読者が同じ記号を 2 つの意味で読むことになるため | 同上 |
| **`scroll` は入れ物の種類ではなく設定。** スクロールする領域は必ず並べ方も持つので、種類にすると `stack` の計算をもう 1 つ書くことになり、「表の領域がスクロールする」が書けなくなる | [画面設計 §3.7](screen-design.md) |
| **タブは見出しを全部・中身を 1 枚だけ描く。** 描かれない頁は「置き場所の無い図形」ではないので下に並べない。切り落としは SVG の切り抜き（id が要る）ではなく幾何でやる——PDF と PPTX に同じ結果を渡すため | 同上 |
| **子が id なら入れ物、子が文字なら部品。** ツリーの項目に id を 20 個与えると項目一覧が 20 行になる。項目定義が要るのはツリー 1 つである | [画面設計 §3.7](screen-design.md) |
| **入れ物の中でのドラッグは並べ替え、外へのドラッグはピン。** 落とす先は引いている間に見せる（`stack` は隙間の帯、`grid` は相手への被せ）。黙って並びが変わる一覧は信用されない | [画面設計 §3.7](screen-design.md) |
| **ツリー・リスト・メニューは「中身で絵が変わる部品」。** 図形の語彙には足さない（括弧 1 組を与えるほどではなく、DrawingML のプリセットにも対応しない）。行は markdown の箇条書きで書き、状態の印は `*`（選択）と `+`（閉じている）の 2 つに固定する | [作図モデル §10.2](diagram-model.md) |
| **行の場所は 1 か所が決める。** 絵を描くときと、押された行を探すときで別に計算したら、押しても選ばれない行が生まれる。描かれなかった行（入りきらなかった行・閉じた枝の中身）はその表に無く、GUI もその行を選ばない | [画面設計 §3.7](screen-design.md) |
| **閉じた枝の中身は描かない。** 印が「この下にまだある」と言っているので、中身まで見えていたら印が嘘になる。行はファイルに残る（**P6**「黙って捨てない」は**消さない**ことであって、**常に描く**ことではない） | 同上 |
| **行の足す・消す・深さは「枝ごと」。** 行だけを動かすと、下にぶら下がっていたものが別の親に付け替わる。深さに穴の空いた木は描けないので、はみ出す操作は断る | 同上 |
| **入れる口は、出す口と同じ手つきにした。** 入れ物の中へドラッグすれば名前が並びに入り、ピンの行が消える。`grid` は**空セルにだけ**入る——埋まったセルに落とすのは、そこにいる誰かを格子の外へ押し出すということである | [画面設計 §3.7](screen-design.md) |
| **選んでいるものが入れ物の中なら、足したものはその次に入る。** 画面の 3 番目の欄を選んで「もう 1 つ」と言った人が欲しいのは 4 番目の欄であって、図の上にピンで浮いた部品ではない | 同上 |
| **部品の一覧は、使っているライブラリから出す。** 画面は `textbox` や `primary` というライブラリの言葉で書かれている。同梱の絵（`ui/*`）の一覧を見せるのは、別の言葉で選ばせることになる | 同上 |
| **部品の区分は、ライブラリの見出し（`# --- 入力 ---`）をそのまま使う。** 40 個を 1 列に並べれば読まれない。区切りは書いた人がもう付けているので、こちらで考え直さない——読むのは「見出しがあること」と「どれがその下にあるか」だけで、文字の意味は読まない | 同上 |
| **VS Code 拡張は、文書の所有権を VS Code に残す**（`CustomTextEditorProvider`）。編集は `WorkspaceEdit` として渡す——取り消し・未保存の点・git の差分・同じファイルを開いているほかのエディタが、全部そのまま効く。自前の窓はそれを作り直すことになる | [提供形態 §1](platforms.md) |
| **拡張の編集も、全文ではなくバイト範囲で渡す。** 全文のほうが実装は簡単だが、取り消しがファイル 1 つぶんになる。製品の約束がそのまま VS Code の単位になるほうが正しい | 同上 |
| **単独の線（`--`）を語彙に加えた。** 画面を仕切る罫線も、何かを指す矢印も、「2 つの図形の関係」ではないので接続では書けない。幾何は**箱の対角線**にして、置き方・大きさの変え方をほかの図形と同じにした | [作図モデル §10.1](diagram-model.md) |
| **線の矢印・太さ・傾きはスタイル層に置く。** 部品が持てるようにするため——「この製品で何かを指す矢印」は 1 回決めれば済む。接続の矢印が意味層にあるのは、そちらは向きが関係そのものだからである | 同上 |
| **線も「近さ」で拾う。** 当たり判定の透明な帯を重ねると、その帯が横切っている図形へのクリックまで奪う（接続線と同じ判断）。交差点では**ポインタに近いほう**を選ぶ | [作図モデル §12.8](diagram-model.md) |
| **部品テンプレートは設計のみ。** 語彙は画面を何枚か描いてからでないと決まらない | [画面設計 §3](screen-design.md) |
| ループは**戻る接続**と**名前付きの群れ**で表す。新しい語彙は要らない | [画面設計 §5](screen-design.md) |

## 4. 表（`.table`）

| 決定 | 出典 |
|---|---|
| **二層構成**。ただし**結合は内容層に置く**（表の形が読めなくなるため） | [表モデル](table-model.md) |
| **列の寄せは区切り行の `:`** で表す（標準 Markdown と同じ）。グリッド部は GFM として読める状態を保つ | 同上 |
| **CSV は取り込み経路であって保存形式ではない** | 同上 |
| 罫線・塗りつぶしは**既定はテーマ、変えたところだけ疎に指定**。セレクタは**ヘッダ名で指す**（位置ではない） | 同上 |
| 値は**テーマのトークンに限る**。直値は書かせない | 同上 |
| 塗りつぶしは**意味トークン 4 種**（`changed` / `pending` / `disabled` / `removed`、**拡張しない**）と**区分トークン** | 同上 |
| **凡例は文書末**。使われたトークンのみ、文書単位で集計 | 同上 |
| セル内はインライン Markdown 可。ブロック要素は**参照方式**（`@1`） | 同上 |
| 自動整形はしない。**明示的な「表を整形」コマンド**を用意する | 同上 |

## 5. 編集 UI

| 決定 | 出典 |
|---|---|
| **ノートブック型**。文章・図・表・画像を 1 ページに混在させる | [編集 UI](editor-model.md) |
| 表は **Excel と同じグリッド操作**（範囲選択・TSV 貼り付け） | 同上 |
| **編集した箇所のバイト範囲だけを置き換える。** 全体を parse → 再 serialize しない | 同上 |
| **改行は LF でも CRLF でも読み、書き足す行はファイルの改行に合わせる**（最初の改行で決める。新しく作るファイルは LF）。LF に揃えさせる設定を利用者のリポジトリに求めない。製品の中の範囲（ソースマップ・指摘のアンカー・編集）は**改行を LF として読んだ本文**で測り、CRLF のファイルに書き戻すときにだけ置き直す。同じコミットの指摘が機械によってずれないためである | [仕様 共通規則 2](../spec/README.md) / [レビュー §3](review-model.md) |
| **本文の同時編集は行わない**（PR レビューゲートを壊すため。「後で」ではなく確定） | [サーバの位置づけ](server-architecture.md) |
| 画像には**注釈を図形レイヤとして重ねる**（画像はバイナリだが注釈はテキストなので差分が読める） | [編集 UI](editor-model.md) |
| **書式バーにカラーピッカーを置かない。** ボタンは 4 つの「意味」であり、各ボタンにテーマの色を添えるに留める | [文字書式 §4](inline-format.md) |

| **行の対応づけは素直な最長共通部分列で取る。** 一意な行を手がかりにする速い方法は、空行の多い文書で端から端まで光る | 同上 |
| **表の分割は「描く範囲を切る」で済む。** 表の構造を作り直さないので、試作に要った収束ループが消えた | [テーマ §6.7](theme.md) |
| **ページ先頭に来た結合セルは、文字をもう一度書いて「（続き）」を添える。** 列に収まらなければ落とす——名前が隣にはみ出すくらいなら、名前だけ出す | 同上 |
| **向きは計測を 2 回するだけ。** 紙の寸法はページごとに持てる（PDF を自前で書いているため）。横向きの要素が無ければ 1 回で終わる | [テーマ §6.2](theme.md) |
| **フォントは HarfBuzz で削る。** pdf-lib 内蔵のサブセッタは CFF を壊し、壊れ方は「取り出せるが描かれない」。テーマの 5 つの面を、面ごとに使う字だけ残して埋める | [PDF エンジン §7.6](pdf-engine.md) |
| **埋め込むフォントから組版の表（GSUB/GPOS）を落とす。** 組版はブラウザが済ませている。残すと埋め込み時に再シェーピングが走り、数字が制御文字として取り出される | 同上 |
| **ブラウザに渡すフォントは、先に削って持たせる。** 20 MB を取りに行かせる案も、サーバで削る案も採らない（後者はサーバ無しで動くという前提に反する） | [PDF エンジン §7.7](pdf-engine.md) |
| **同梱した字の外に出たら、名指しで報告する。** 人名が静かに消えた PDF を配るよりはよい | 同上 |
| **同梱したサブセットは画面にも使う**（`@font-face`）。テーマがフォントを名指しできるのは、それが入っている環境だけ。外へ取りに行かないまま、紙と同じ字面になる | 同上 |
| **削った結果を見てから埋める。** HarfBuzz は頼みすぎると輪郭の無いフォントを黙って返す。埋めれば「取り出せるが白紙」になり、テキスト検証は通ってしまう | 同上 |
| **エディタは設定画面を持たない。設定は値として受け取る。** 画面は器（VS Code の `contributes.configuration` / Web シェル）が持つ | [設定モデル](settings-model.md) |
| **狭い画面での配置は器の責務。** エディタ自身は幅に追従する（タブは横スクロール、バーは折り返す）が、周りのペインをどう畳むかは器が決める | 同上 |
| **設定にするのは流儀が実在して割れている項目だけ。** 最初の項目は「編集を確定するキー」、既定は `Ctrl+Enter` | 同上 |
| **確定に割り当てなかった `Enter` は、修飾キー付きでも必ず改行を入れる。** 押して何も起きないのは誤動作より悪い | 同上 |
| **シート制**。縦一列に流さず、`---` で区切られた範囲を 1 シートとして 1 枚ずつ表示する。**新しい記法は作らない** | [シートモデル](sheet-model.md) |
| **シート名はファイルに書かない。** シート内の最初の見出しから計算する | 同上 |
| **シートは版面の単位であって、採番・参照の単位ではない。** シートごとにファイルも分けない | 同上 |
| タブの操作（追加・削除・並べ替え・改名）は**すべて 1 回のバイト範囲書き換え**。並べ替えは動いた範囲だけを書き、シートの中身は逐語的に運ぶ | [シートモデル §3.1](sheet-model.md) |
| **空のシートも 1 枚として数える。** 捨てると「＋」でタブが増えず、最後の 1 行を消すとタブが消える | [シートモデル §3.2](sheet-model.md) |
| 改名は**名前の出どころである見出しを書き換える**。見出しの無いシートは改名できないと言う | 同上 |

## 9. 実装

| 決定 | 出典 |
|---|---|
| **TypeScript 単一言語**。C# は使わない。素の JavaScript は書かない | [実装スタック](stack.md) |
| `ErCreator.Canvas` は**再利用しない**が、**移植元の参照実装**として扱う | 同上 |
| **コアはサーバ無しで全機能が動く。** コメント収集サーバは self-host 可能な**オプショナル層** | [サーバの位置づけ](server-architecture.md) |
| **正本は常に Git。** サーバは状態を持たず、コメントを Git に書き戻すだけ | 同上 |
| **デスクトップ専用アプリは作らない。VS Code 拡張が担う**（Tauri / Electron は採らない） | [提供形態](platforms.md) |
| **次の投資先は AI 連携**（デスクトップアプリを作る労力を回す） | 同上 |
| **Web 版は「お試しと閲覧」が既定。** ローカルフォルダは Chromium 系デスクトップでのみ開ける | 同上 |
| **リモート Git 連携は Web 版の必須機能。** 認証中継サーバが要るが、**設計書の中身は通らない**（GitHub REST API が CORS 対応のため直叩きできる）。`git clone` 方式は CORS プロキシに中身が通るので採らない | 同上 |
| **Chromium 系ではローカルフォルダを開いて執筆できる**（File System Access）。ファイルは実ファイルなので利用者の git と共存する。ただし**コミットが無いのでレビュー機能は成立しない** | [提供形態 §3.3](platforms.md) |
| **ZIP 書き出しは全環境で提供する。** OPFS しか使えない環境の唯一の持ち出し口。範囲は[ビルド単位](build-model.md)と同じ参照閉包 | [提供形態 §3.4](platforms.md) |
| **ZIP は無圧縮（store 形式）で自前生成する。** 中身はテキストと圧縮済み画像で圧縮率が効かず、依存を増やす理由が無い | 同上 |
| **サーバ無しで完全に動くのは VS Code 拡張と CLI**。Web 版のリモート連携のみ例外 | [提供形態](platforms.md) |
| **認証中継は開発元ホスト版と self-host の両方を提供する。** 片方だけでは「試せない」か「企業に入れない」のどちらかになる | 同上 |
| **認証中継とコメント収集サーバは 1 つにまとめる**（どちらも薄く、状態を持たず、self-host 可能） | 同上 |
| **中継サーバはオープンソースとして公開する**（MIT / Apache-2.0 を推奨）。閉じたバイナリでは self-host の目的（審査を通す）を果たせない。公開範囲に製品の差別化要因は含まれない | 同上 |
| Web 版は **`client_id` と中継 URL を差し替えられる**（self-host の前提） | 同上 |
| **改訂履歴は Git のコミット履歴から生成する。** `Doc-Revision:` トレーラで選別し、範囲は参照閉包。手書きがあれば優先 | 同上 |

## 11. 意識的に採らなかった選択肢

| 採らなかったもの | 理由 |
|---|---|
| Typst での PDF 生成 | **テーマが二重化する**（HTML 出力が必須のため） |
| 中間モデルを独自ファイル形式（`.docmlx`）にする | 地が Markdown に決まり、**中間モデルはファイルでなくなった** |
| モデル要素 ID でコメントを固定する | **ID 安定性という未解決問題**を抱え込む。バイト範囲なら既知の問題に置き換わる |
| 本文の同時編集 | **PR レビューゲートが消える**。モデルが CRDT 前提になり、差別化に使う予算を食う |
| サーバ前提 | アカウント・テナント・顧客のセキュリティ審査が常について回る |
| Excel 資産のインポート / Office 出力 | スコープを絞る判断。商流で弾かれる場面が残ることは承知の上 |
| CSV を表の保存形式にする | 結合・罫線・寄せ・セル内 Markdown が載らない |
| 章番号込みの図表番号（図 3.1） | 図を触っていないのに**章の挿入で番号が変わる** |
