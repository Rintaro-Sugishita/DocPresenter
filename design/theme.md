# テーマ設計案 — フォントとスタイルの指定

作成: 2026-09-21 / 対象: [未決事項 A-4](open-issues.md)（テーマの定義形式）のうち、フォントに関する部分
関連: [PDF 生成エンジン](pdf-engine.md) / [表モデル](table-model.md) / [出力モデル](output-model.md)

## 0. 決定事項（ロック済み）

- **テーマは CSS で書く。** [PDF をブラウザで組版する](pdf-engine.md)決定の帰結として、テーマ言語は自動的に CSS になる。
- **フォントのサイズ・ウェイト・行送り・字送りは自由に指定できる。**
- **フォントファミリは「埋め込み可能で、テーマが同梱しているもの」に限る**（§2）。OS のシステムフォントは指定できない。
- 既定で **Noto Sans CJK JP（ゴシック）/ Noto Serif CJK JP（明朝）/ 等幅**を同梱する。

## 1. テーマが CSS であること

PDF は HTML を組版して作る（[決定済み](pdf-engine.md)）。したがって

> **画面の HTML も、PDF も、まったく同じ CSS で組まれる。**

テーマは独自形式を発明せず、CSS そのものとする。フォントに関しては次がそのまま使える。

```css
:root {
  --font-heading: "Noto Sans CJK JP";
  --font-body:    "Noto Serif CJK JP";
  --font-mono:    "Noto Sans Mono CJK JP";
}

body   { font-family: var(--font-body); font-size: 10.5pt; line-height: 1.8; }
h1, h2 { font-family: var(--font-heading); font-weight: 700; }
code   { font-family: var(--font-mono); font-size: 0.9em; }
```

**サイズ・ウェイト・行送り・字送りは自由。** ここに制限を設ける理由が無い。

## 2. フォントファミリだけは自由にできない

### 理由 — PDF に埋め込むにはバイト列が要る

[検証](../prototype/pdf-text/FINDINGS.md)のとおり、PDF はフォントを**埋め込んで**作る。ここから二つの制約が出る。

1. **ブラウザからローカルのシステムフォントのバイト列は取得できない。** 画面には出せても PDF には入れられない
2. **OS 同梱フォント（游ゴシック・メイリオ・ヒラギノ等）は再配布・埋め込みが制限される**

`font-family: "游ゴシック"` と書けた場合に何が起きるかを考えると分かりやすい。

| | 画面（HTML） | PDF |
|---|---|---|
| 游ゴシックがある環境 | 游ゴシックで表示 | **埋め込めないので代替フォント** |
| 無い環境 | 代替フォント | 代替フォント |

**画面と PDF が一致しない。** これは[直値を禁止してトークンに限定した](table-model.md)のとまったく同じ問題であり、同じ理由で禁じる。

> **テーマで使えるのは、そのテーマが同梱しているフォントだけ。**

### フォントの持ち込みはできる

同梱していれば良いので、利用者が自分のフォントをテーマに入れることは妨げない。

```
theme/
  theme.css
  fonts/
    CorporateGothic.otf
```

```css
@font-face { font-family: "Corporate Gothic"; src: url("fonts/CorporateGothic.otf"); }
```

**そのフォントを埋め込んで良いかというライセンス上の責任は、持ち込んだ利用者が負う。** ビルド時に
フォントの埋め込み許可ビット（`fsType`）を確認し、禁止されていれば警告する。

### 既定で同梱するもの

| 用途 | フォント | 備考 |
|---|---|---|
| ゴシック | Noto Sans CJK JP | 44,810 字。SIL OFL 1.1 |
| 明朝 | Noto Serif CJK JP | 同上 |
| 等幅 | Noto Sans Mono CJK JP | 同上 |

設計書に必要な書体は、実務上ほぼこの 3 種で足りる。

## 3. 和欧文混植はブラウザが解決する

```css
body { font-family: "Inter", "Noto Serif CJK JP"; }
```

このように書けば、ブラウザが**文字ごとに**フォントを解決する。欧文は Inter、和文は Noto Serif になる。

**我々はレイアウト済みの DOM を読む**ため（[PDF パイプライン](pdf-engine.md)）、**どのテキスト実行体がどのフォントで
組まれたかは、読む時点で既に決まっている**。あとはそれぞれを埋め込むだけでよい。

混植のためのフォールバック規則を自前で実装する必要が無い。ブラウザを組版に使うことの副次的な利点である。

### 複数書体の埋め込みは検証済み

ゴシックと明朝を 1 つの PDF に埋め込んで、描画・抽出とも正常であることを確認した。
事前サブセットのため **2 書体で 35.5 KB** に収まる（[検証結果](../prototype/pdf-text/FINDINGS.md)）。

## 4. ウェイトは別フォントとして埋め込む

太字は合成（fake bold）ではなく、**そのウェイトのフォントファイルを埋め込む**。合成太字は日本語で
品質が落ちるうえ、PDF のテキストとしても扱いが悪い。

サブセット化するため、ウェイトを増やしても増加分は小さい。ただし**テーマが使うウェイトの数だけ
フォントファイルが要る**ため、同梱セットのサイズには影響する。

## 5. 欠字検出はテーマ依存になる

[検証](../prototype/pdf-text/FINDINGS.md)で、**フォントが持たない字は「描画は豆腐、抽出は消滅」**という
壊れ方をすることが分かっており、書き出し前の検出を必須としている。

この検出は**テーマが選んだフォントに対して**行う。したがって

- テーマを差し替えると、欠字の有無が変わる
- 字種カバーの狭いフォントを持ち込むと、欠字が増える

ビルド時に「このテーマのフォントでは次の文字が出せない」と具体的に示す必要がある。
