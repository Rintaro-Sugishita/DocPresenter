# 変更箇所の表示 — 差分から自動で付ける

作成: 2026-09-26 / 対象: 要件 R13
関連: [表モデル](table-model.md) / [文字書式](inline-format.md) / [レビューモデル](review-model.md) / [提供形態](platforms.md)

## 0. 決定事項（ロック済み）

- **変更箇所は人が塗らない。Git の差分から自動で付ける**（§1）。
- **差分の起点は指定する** — コミット、タグ、ブランチ、または比較対象のフォルダ（§2）。
- **追加・削除・変更に割り当てる色は利用者が決める**（§3）。既定はテーマが持つ。
- **成果物（HTML / PDF / PPTX）に出す。** ソースファイルには書かない（§4）。
- **削除された部分をどう見せるかは出力の設定**（消す / 取り消し線で残す）（§4）。

## 1. なぜ人が塗らないのか

以前は意味トークン（`changed` / `pending` / `disabled` / `removed`）を語彙として固定し、
「変更あり」を著者が手で付ける想定だった。**これは撤回する。**

理由は単純である。**Git で差分が取れるのに、変更箇所を手で塗る運用は続かない。**

- 塗る作業が発生する。直したら塗り、レビューが終わったら剥がす
- 剥がし忘れる。前回の「変更あり」が残ったまま次の版が出る
- そもそも**塗り忘れたら差分と食い違う**。食い違った瞬間、色は信用されなくなる

これは[P1](decisions.md)（**計算で出せるものはファイルに書かない**）そのものである。
図表番号をファイルに書かないのと同じ理由で、変更箇所もファイルに書かない。

> **変更箇所は、著者の申告ではなく、リポジトリの事実である。**

### 手で色を付けたいときは、別の目的である

色を手で付ける場面は無くならない。ただしそれは「変更した」ではなく「**目立たせたい**」である。
目立たせたいことに意味の語彙は要らないので、[色は自由に選べる](inline-format.md)ようにした。

**意味の語彙をやめて失ったもの**を正直に書いておく。

| 失ったもの | どう埋めるか |
|---|---|
| 凡例の自動生成 | 変更・削除の凡例は**差分表示が自前で出す**（§4）。任意の色には凡例が要らない |
| AI が「赤」の意味を読めない | 変更箇所は差分として出せるので、**AI には色ではなく差分そのものを渡す**（R9） |
| 白黒印刷での識別 | 差分表示は**色に加えて記号**（`+` / `-`・網掛け）を併用する（§4） |

いずれも、**変更の表示を差分に移したことで、むしろ強くなっている**。

## 2. 何と比較するか

```
docpresenter build docs/auth-design.md --diff-from v1.2
docpresenter build docs/auth-design.md --diff-from HEAD~3
docpresenter build docs/auth-design.md --diff-from ../release-1.2/
```

| 起点 | 用途 |
|---|---|
| **コミット / タグ / ブランチ** | 「前回の版から何が変わったか」。最も普通の使い方 |
| **フォルダ** | Git を使っていない相手から受け取った版との比較。納品物どうしの比較 |

比較の範囲は[ビルド単位](build-model.md)と同じ**参照閉包**とする。
本文が変わっていなくても、参照している `.dgm` や `.table` が変われば、その図表は変更として出る。

### 図と表の差分

| 対象 | 何を差分とするか |
|---|---|
| 本文 | 行・文字単位の差分 |
| **表** | **セル単位**。行・列の追加と削除も含む |
| **図** | **要素単位**（図形・接続の追加 / 削除 / ラベルの変更） |

表と図は[モデルとして持っている](table-model.md)ので、**テキストの行差分ではなくモデルの差分が取れる**。
`.table` の 1 行の差分を「この行が変わった」ではなく「**このセルが変わった**」と言える。
これは本製品が図表を専用形式で持っていることの、はっきりした利益である。

レイアウトだけが変わった図（[ピン留めの座標](diagram-model.md)だけの差分）は**変更として出さない**。
意味が変わっていないためである。3 層モデルがここでも効く。

## 3. 色は利用者が決める

```yaml
# テーマ、または front matter
diff:
  added:    "#e6f4e9"   # 追加された部分の網掛け
  removed:  "#fde8e8"   # 削除された部分の網掛け
  changed:  "#fdf0d5"   # 変更された部分の網掛け
  show-removed: strike   # none | strike
```

既定はテーマが持つ。文書ごとに上書きできる。

## 4. 出力

差分表示は**成果物にだけ出る**。ソースファイルには 1 バイトも書かない。

| 出力 | 表示 |
|---|---|
| HTML | 網掛け ＋ `+` / `-` の記号。凡例を文書末に |
| PDF | 同上。白黒印刷でも読めるよう、色に加えて網掛けパターン |
| PPTX | 図形の塗り。編集可能な図としての性質は保つ |

**削除された部分の扱いは設定で選ぶ。**

- `none` — 消えたものは出さない。現在の版として正しい見た目になる
- `strike` — 取り消し線で残す。「何が消えたか」を相手に見せる、改訂レビュー向け

## 5. レビューとの関係

[レビューモデル](review-model.md)のコメントは**コミットハッシュ＋バイト範囲**にアンカーする。
差分表示も同じ土台の上にある。

> コメントは「この版のここについて言っている」、差分は「この版とあの版で何が違うか」。
> **どちらも版の同一性を Git に預けている。**

差分の起点を「前回レビューしたコミット」にすれば、**前回のレビュー以降の変更だけ**を出せる。
これが実務で最も欲しい形である。

## 7. 残る未決定事項

- **移動の扱い** — 節の移動を「削除＋追加」と見せるか「移動」と見せるか
