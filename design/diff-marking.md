# 変更箇所の表示 — 差分から自動で付ける

作成: 2026-09-26 / 対象: 要件 R13
関連: [表モデル](table-model.md) / [文字書式](inline-format.md) / [レビューモデル](review-model.md) / [提供形態](platforms.md)

## 0. 決定事項（ロック済み）

- **変更箇所は人が塗らない。Git の差分から自動で付ける**（§1）。
- **差分の起点は指定する** — コミット、タグ、ブランチ、または比較対象のフォルダ（§2）。
- **追加・削除・変更に割り当てる色は利用者が決める**（§3）。既定はテーマが持つ。
- **成果物（HTML / PDF / PPTX）に出す。** ソースファイルには書かない（§4）。
- **削除された部分をどう見せるかは出力の設定**（消す / 取り消し線で残す）（§4）。

## 1. なぜ人が塗らないのか

以前は意味トークン（`changed` / `pending` / `disabled` / `removed`）を語彙として固定し、
「変更あり」を著者が手で付ける想定だった。**これは撤回する。**

理由は単純である。**Git で差分が取れるのに、変更箇所を手で塗る運用は続かない。**

- 塗る作業が発生する。直したら塗り、レビューが終わったら剥がす
- 剥がし忘れる。前回の「変更あり」が残ったまま次の版が出る
- そもそも**塗り忘れたら差分と食い違う**。食い違った瞬間、色は信用されなくなる

これは[P1](decisions.md)（**計算で出せるものはファイルに書かない**）そのものである。
図表番号をファイルに書かないのと同じ理由で、変更箇所もファイルに書かない。

> **変更箇所は、著者の申告ではなく、リポジトリの事実である。**

### 手で色を付けたいときは、別の目的である

色を手で付ける場面は無くならない。ただしそれは「変更した」ではなく「**目立たせたい**」である。
目立たせたいことに意味の語彙は要らないので、[色は自由に選べる](inline-format.md)ようにした。

**意味の語彙をやめて失ったもの**を正直に書いておく。

| 失ったもの | どう埋めるか |
|---|---|
| 凡例の自動生成 | 変更・削除の凡例は**差分表示が自前で出す**（§4）。任意の色には凡例が要らない |
| AI が「赤」の意味を読めない | 変更箇所は差分として出せるので、**AI には色ではなく差分そのものを渡す**（R9） |
| 白黒印刷での識別 | 差分表示は**色に加えて記号**（`+` / `-`・網掛け）を併用する（§4） |

いずれも、**変更の表示を差分に移したことで、むしろ強くなっている**。

## 2. 何と比較するか

```
docpresenter build docs/auth-design.md --diff-from v1.2
docpresenter build docs/auth-design.md --diff-from HEAD~3
docpresenter build docs/auth-design.md --diff-from ../release-1.2/
```

| 起点 | 用途 |
|---|---|
| **コミット / タグ / ブランチ** | 「前回の版から何が変わったか」。最も普通の使い方 |
| **フォルダ** | Git を使っていない相手から受け取った版との比較。納品物どうしの比較 |

比較の範囲は[ビルド単位](build-model.md)と同じ**参照閉包**とする。
本文が変わっていなくても、参照している `.dgm` や `.table` が変われば、その図表は変更として出る。

### 図と表の差分

| 対象 | 何を差分とするか |
|---|---|
| 本文 | 行・文字単位の差分 |
| **表** | **セル単位**。行・列の追加と削除も含む |
| **図** | **要素単位**（図形・接続の追加 / 削除 / ラベルの変更） |

表と図は[モデルとして持っている](table-model.md)ので、**テキストの行差分ではなくモデルの差分が取れる**。
`.table` の 1 行の差分を「この行が変わった」ではなく「**このセルが変わった**」と言える。
これは本製品が図表を専用形式で持っていることの、はっきりした利益である。

レイアウトだけが変わった図（[ピン留めの座標](diagram-model.md)だけの差分）は**変更として出さない**。
意味が変わっていないためである。3 層モデルがここでも効く。

## 3. 色は利用者が決める

```yaml
# テーマ、または front matter
diff:
  added:    "#e6f4e9"   # 追加された部分の網掛け
  removed:  "#fde8e8"   # 削除された部分の網掛け
  changed:  "#fdf0d5"   # 変更された部分の網掛け
  show-removed: strike   # none | strike
```

既定はテーマが持つ。文書ごとに上書きできる。

## 4. 出力

差分表示は**成果物にだけ出る**。ソースファイルには 1 バイトも書かない。

| 出力 | 表示 |
|---|---|
| HTML | 網掛け ＋ `+` / `-` の記号。凡例を文書末に |
| PDF | 同上。白黒印刷でも読めるよう、色に加えて網掛けパターン |
| PPTX | 図形の塗り。編集可能な図としての性質は保つ |

**削除された部分の扱いは設定で選ぶ。**

- `none` — 消えたものは出さない。現在の版として正しい見た目になる
- `strike` — 取り消し線で残す。「何が消えたか」を相手に見せる、改訂レビュー向け

## 5. レビューとの関係

[レビューモデル](review-model.md)のコメントは**コミットハッシュ＋バイト範囲**にアンカーする。
差分表示も同じ土台の上にある。

> コメントは「この版のここについて言っている」、差分は「この版とあの版で何が違うか」。
> **どちらも版の同一性を Git に預けている。**

差分の起点を「前回レビューしたコミット」にすれば、**前回のレビュー以降の変更だけ**を出せる。
これが実務で最も欲しい形である。

## 6. 実装の段階

| 段階 | 内容 | 状況 |
|---|---|---|
| 1 | 差分の型と、差分を成果物に描くレンダリング | **実装済み**（§6.1） |
| 2 | テキストの行・文字差分 | **行まで実装済み。** 文字単位は未実装 |
| 3 | 表のセル差分・図の要素差分 | **実装済み** |
| 4 | Git からの取得（CLI / VS Code は直接、Web 版は[REST API](platforms.md)） | **CLI・VS Code は実装済み**（`git show`。VS Code は §6.3）。Web 版は未実装 |

段階 4 は環境ごとに手段が違う（CLI と VS Code は git そのもの、Web 版は Compare API）。
**段階 1〜3 は環境に依存しない**ので、先に固めた。

### 6.1 実装したもの（2026-09-29）

```
node tools/build.mjs --in <作業域> --diff-from HEAD~3
node tools/build.mjs --in <作業域> --diff-from ../release-1.2/
```

| 比べるもの | どう比べるか | 置き場所 |
|---|---|---|
| 本文 | 行の最長共通部分列。変わった行のバイト範囲を返す | `packages/build/src/diff.ts` |
| 表 | **セル単位。** 列は見出しの文字で、行は中身で対応づける（§6.3） | 同上 |
| 図 | **要素単位。** 図形と接続を id で対応づける | 同上 |
| 描画 | クラス名（`dp-diff-added` 等）。色はテーマが決める | `packages/markdown/src/html/diff.ts` |

**印はクラス名で出す。** 何色かはテーマの仕事で、レンダラは「変わった」としか言わない。
PDF は[組版済みの DOM を読む](pdf-engine.md)ので、**HTML に印が付けば PDF にも自動的に付く**。
PPTX だけは色を自分で持つ——スライドに CSS は無いため（[PPTX モデル §10](pptx-model.md)）。

**行の対応づけは素直な最長共通部分列で取る。** 最初は「両方に一度だけ現れる行」を
手がかりにする速い方法を書いたが、**空行はどの文書にも何度も出る**ため、
手がかりの間が丸ごと「変更」になった。**触っていない文書が端から端まで光る**という壊れ方をする。
数百行の設計書なら素直な表で足りる。

**位置だけの違いは変更にしない**（`layout` の差分を見ない）。
[3 層モデル](diagram-model.md)がここで効く——図を整えた人が、
書き換えたことにされない。検証（`tools/check-diff.mjs`、10 項目）の 1 項目はこれである。

### 6.2 まだやっていないこと

- **文字単位の差分。** 段落は行単位で光る。どこが変わった行かは分かるが、どの語かは分からない
- **削除を PPTX に出すこと。** スライドに消えたものを置く場所が無いので出さない（§6.4）
- **消えた列を表の中に戻すこと。** 結合や列幅と絡むので、表の下に名前で出すだけにした
- **Web 版の取得経路**（Compare API）
- **差分の色を文書の frontmatter で上書きする**（[§3](#3-色は利用者が決める)）。いまはテーマのみ

### 6.3 VS Code から使う（2026-11-14）

利用者の要望で、CLI だけだった機能に画面を付けた（`packages/app-vscode/src/changes-command.ts`）。

- 文書の上の書き出しバーに **「変更箇所付き…」**。押すと QuickPick で**比べる版**→**形式**を選ぶ。
  版の候補は「この文書を変えたコミット」（`git log -- <文書>`）・タグ・ほかのブランチ。直接入力と別フォルダも選べる。
  リポジトリでない作業場では、いきなりフォルダを選ぶ。
- 出力は `<文書名>.changes.<形式>` に置く。**ふつうの出力を上書きしない**ため（納品用を印付きで潰さない）。
- 前回の版と形式は `workspaceState` に覚える。
- 当初は `show-removed` を画面に出さなかった（描く処理が無かった）。§6.4 で描くようにしたので、PDF・HTML では 3 つ目の問いとして聞く。

あわせて**表の行の対応づけを直した。** 先頭セルの文字で対応づけていたが、設計書の表の先頭列は
「分類」を `^` で結合したものや `#` の連番であることが多く、**同じ鍵の行が並んで、1 セル直すと隣の行まで光った**。
いまは、①全セルが同じ行を先に対応づけ（入れ替えは変更にならない）、②残りは同じセルが最も多い行と対応づける。
印は「何行目の何列目」で渡す（`TableMarks` の鍵を文字から位置に変えた）。

### 6.4 消えたものを取り消し線で見せる（2026-11-17）

利用者の要望で、`show-removed: strike` の描画を入れた。**頼まれたときだけ**出す。既定（`none`）は今までどおり、今の版にあるものにだけ印を付ける。

- **本文**（`removedLines`、`packages/build/src/diff.ts`）。行の最長共通部分列で余った**前の版の行**を、今の版の「その行が立っていた位置」（置き換えた行の頭、または次に続く行の頭）のバイト位置と組にして渡す。
  - 書き換えた行は、古い行が新しい行の前に取り消しで出る。赤線で直す校正と同じ読み方になる。
  - 空行だけの削除と front matter（設定であって本文ではない）は出さない。
  - 描くとき（`removedPlacer`、`packages/markdown/src/html/render.ts`）は、本文のかたまりを**その行の位置で切って**間に差し込む。1 つのかたまりに段落が並んでいても、消えた段落はその段落の間に出る。切った各片には今までどおり追加・変更の印が付く（印の粒度がかたまりから片に細かくなる）。
  - 消えた行は Markdown として組む（取り消し線と破線の帯）。見出しや `@import` の行も、書いてあった文字のまま出る。番号付きの箇条を途中で切ると、番号は片ごとに振り直される。
- **表**（`tableDiff`）。対応の付かなかった前の版の行を、対応の付いた次の行の上に戻す。結合が下へ続いている所には差し込めないので、結合の下へずらす。書き換えたセルは、元の文字を取り消しで今の文字の前に置く。消えた列は表の下に名前で出す。行を範囲で取り出した表（`rows=`）には消えた行を戻さない。
- **図**（`diagramDiff`）。消えた図形と矢印には置き場所が無い（配置の層から消えている）ので、図の下に「図から削除：」として文字で並べる。
- **PPTX には出さない。** VS Code でも PPTX を選んだときは問いを出さない。
- 検証は `tools/check-diff.mjs` に 9 項目を足した（消えた段落・その位置・取り消し線・セルの元の文字・消えた行・図から消えたもの・凡例・PDF・頼まなければ出ないこと）。

## 7. 残る未決定事項

- **文字単位の差分の粒度** — 日本語で語単位の差分を出すか、文字単位で十分か
- **図の要素差分の表示** — 追加された図形を塗るのか、枠線で示すのか
- **移動の扱い** — 節の移動を「削除＋追加」と見せるか「移動」と見せるか
- **差分の起点を文書に書けるか** — front matter に `diff-from:` を持たせるか、ビルド時の指定だけにするか
