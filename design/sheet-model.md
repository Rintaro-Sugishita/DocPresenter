# シートモデル設計案 — 縦一列をやめる

作成: 2026-09-23 / 対象: 編集 UI が「ひたすら縦に続く」問題
関連: [編集 UI 設計案](editor-model.md) / [出力モデル](output-model.md)

## 0. 決定事項（ロック済み）

- **シートに新しい記法は作らない。`---` で区切られた範囲がそのままシートである**（§1）。
- **シート名はファイルに書かない。** シート内の最初の見出しから計算する（§2）。
- **編集 UI は 1 シートずつ表示し、下端にタブを並べる**（§3）。
- **シート境界は HTML / PDF で強制改ページ**、PPTX でスライド分割（§4）。
- **シートは版面の単位であって、採番・参照の単位ではない**（§5）。
- **シートごとにファイルを分けない。** 文書は 1 ファイルのままとする（§6）。
- **タブの操作はすべて 1 回のバイト範囲書き換えとして書き戻す**（§3.1）。
- **空のシートも 1 枚として数える**（§3.2）。

## 1. なぜ新しい記法を作らないか

長い文書が縦に延々と続くと読む気が失せる。Excel が優れているのは、**作業単位が最初から区切られていて、今どこにいるかが常に分かる**ことである。これを取り込みたい。

しかし「シート」という概念のために新しい記法を足すのは誤りである。**区切りはすでにある。**

| 出力 | `---` の意味 |
|---|---|
| PDF | 改ページ |
| PPTX | スライド分割 |
| **編集 UI** | **シートの区切り** |
| HTML | 強制改ページ（§4 で改める） |

`---` はもともと「出力単位の境界」として決めたものだった（[出力モデル §2](output-model.md)）。編集画面の単位も出力単位に一致させれば、**著者が見ている 1 画面が、そのまま出力の 1 ページになる**。区切りを二重に持つより、はるかに分かりやすい。

> **シート ＝ `---` で区切られた範囲。** 定義はこれだけである。

## 2. シート名は計算する

タブに出す名前をファイルに書かせない。**シート内で最初に現れる見出しの文字列を使う**。見出しが無ければ「シート N」とする。

理由は [P1](decisions.md)（計算で出せるものはファイルに書かない）そのものである。名前を別に持たせれば、見出しを直したときに**タブだけ古い名前のまま残る**。同じ事実が二箇所にある状態は必ず食い違う。

```markdown
---

## 3. 認証方式          ← このシートのタブは「3. 認証方式」
                          （番号も採番結果から計算する）
```

タブ名が気に入らないなら見出しを直す。見出しとタブ名が一致していることは、むしろ文書として正しい。

## 3. 編集 UI

```
┌──────────────────────────────────────────┐
│  （1 シート分の内容だけを表示）              │
│                                          │
│  ## 3. 認証方式                           │
│  本文…                                    │
│  ┌────────────────┐                      │
│  │ [図] login-flow │  ← 埋め込みオブジェクト  │
│  └────────────────┘                      │
│                                          │
├──────────────────────────────────────────┤
│ 概要 │ 2. 全体構成 │ ▸3. 認証方式 │ 4. 画面 │ ＋│
└──────────────────────────────────────────┘
```

- **タブは下端**（Excel と同じ位置）。上端はツールバーに使う
- **タブのドラッグでシートを並べ替える** = `---` で区切られた範囲ごとの移動。ソースの並べ替えとして書き戻す
- **「＋」で新しいシート** = 末尾に `---` を 1 個足す
- 通し読みが要るときのために**全シート連結表示への切り替え**を残す。既定はシート単位
- **Ctrl+PageUp / PageDown** でシートを移動する（表計算ソフトと同じ）

シート内は[これまでどおり](editor-model.md) Markdown を地とし、図・表・画像が埋め込みオブジェクトとして浮く。**シート制は、その外側に 1 段の区切りを足しただけ**である。

### 3.1 操作はすべてバイト範囲の書き換えになる

シートという実体はファイルの中に無い。あるのは `---` だけである。したがってタブの操作は**モデルを組み直して書き出す**のではなく、**バイト範囲の置換 1 個**になる。

| 操作 | 書き換える範囲 | 書き込む内容 |
|---|---|---|
| 追加 | 直前のシートの末尾（長さ 0） | `\n\n---\n` |
| 削除 | 区切り 1 個とシート本体 | 空 |
| 並べ替え | **動かした位置から動かした先までの全シート** | 並べ替えた本体を `\n\n---\n\n` で連結 |
| 改名 | 名前の出どころである**見出しの行** | 書き換えた見出し |

並べ替えだけは範囲が広い。**動いたのはその範囲だからである。** 範囲の外は 1 バイトも変わらず、範囲の中も**各シートの中身は逐語的に運ぶ**。正規化されるのはシートとシートの継ぎ目だけである。

改名に特別な処理は要らない。**名前の出どころは見出ししかない**ので、見出しを書き換えればよい。見出しの無いシートは改名できないと言う（[P6](decisions.md) — 黙って捨てない）。`{#sec-x}` のようなラベルは見出し行の一部としてそのまま残る。

### 3.2 空のシートを捨てない

「＋」で作るシートは**空**である。プレースホルダの見出しを置くことも考えたが、どうせ消される。表計算ソフトの新しいシートも空である。

ただしこれは、**空のシートを 1 枚として数える**ことを要求する。数えないと、

- 「＋」を押してもタブが増えない
- シートの最後の 1 行を消した瞬間にタブが消える

という挙動になる。ファイル末尾に取り残された `---` も、黙って無視するより**空のタブとして見せて消させる**ほうがよい。

## 4. 出力での扱い — HTML の方針を改める

[出力モデル §4](output-model.md) では「HTML は連続表示なのでページという概念が無い」とし、`---` は区切りとして解釈するがガイド表示に留めていた。**これを改める。**

| 出力 | シート境界の扱い |
|---|---|
| PDF | 改ページ（変更なし） |
| PPTX | スライド分割（変更なし） |
| **HTML** | **強制改ページ。** `<section class="dp-sheet">` に分け、印刷時は `break-before: page` |

理由は、著者が見ている単位と読者が見る単位を一致させるためである。著者がシート単位で書いたのに、HTML だけが境界を無視して一続きに流すなら、**シート制は編集画面だけの飾りになる**。画面上では従来どおり境界をガイドとして示し、印刷とページ送りの単位としては実際に切る。

`---` は依然として `<hr>` にはならない。区切りであって水平線ではない、という判断は変わらない。

## 5. シートは採番の単位ではない

図表番号・章番号・相互参照は[文書単位の通し番号](reference-syntax.md)のままとする。シートをまたいで `@fig-login-flow` と書ける。

**シートは版面の単位であって、内容の単位ではない。** シートを分けたり並べ替えたりしただけで番号が振り直されるなら、シートは気軽に触れないものになってしまう。これは「章番号込みの図表番号を採らない」判断と同じ理由である。

## 6. ファイルは分けない

1 シート 1 ファイルにはしない。

- **差分が読めなくなる。** シートの移動がファイルの移動として現れ、中身の変更と区別できない
- **参照が壊れる。** 文書内参照がファイル間参照になる
- **文書が 1 ファイルであることは、この製品の前提**である（[編集 UI](editor-model.md)）

シートは**ファイルの構造ではなく、ファイルの見え方**である。

## 7. `---` の位置づけの変化

[出力モデル §5](output-model.md) には「`---` を大量に打たなければ体裁が整わない状態は、テーマの設計が間違っている兆候」と書いた。シート制では `---` が構造的な区切りになるため、この記述を次のように改める。

> **著者が意図した版面の単位は `---` で表す**（シート）。**全文書に一律で効かせたい体裁の規則はテーマが持つ**（章の頭で改ページ、表をまたがせない等）。`---` をテーマの代わりに使っているなら、それはテーマの設計が間違っている兆候である。

打つ数の多寡ではなく、**何のために打っているか**で判断する。

## 8. 実装して分かったこと

- **シートを切り替えるだけでタブバーを作り直してはいけない。** 作り直すとダブルクリックの後半が「すでに無い要素」に落ちる。選択で変えるのは表示と選択状態だけにする
- **1 枚だけ表示しているときに改ページガイドは出さない。** 境界の相手が画面に居ないのに境界を描いても意味が無い
- 改名の確定（Enter）はタブを作り直すので `blur` が続けて飛ぶ。**確定は 1 回**に抑える必要がある

いずれも、[操作を実際に動かして確かめる道具](../tools/check-editor.mjs)を書いて初めて分かった。作図のときと同じで、**UI は動かすまで検証できない**。

## 9. 残る未決定事項

- **シートをまたぐ選択・検索** — 全シート連結表示に切り替えるのか、シート横断で検索するのか
- **タブが増えすぎたとき** — 折りたたみ、グループ化、あるいは制限
- **シート単位の権限やレビュー状態** — シートごとに「レビュー済み」を持たせるかどうか
- **シート内の編集** — 本文・図・表の編集はまだ入っていない。現状は表示と、シートそのものの操作だけ
- **取り消し（undo）** — 書き換えは 1 個の `Edit` なので積むだけでよいが、まだ積んでいない
