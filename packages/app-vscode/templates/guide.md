# DocPresenter 設計書の書き方（エージェント向け仕様）

このリポジトリの設計書は DocPresenter の形式で書かれている。Claude Code などのエージェントが
文書を書き足す・直すときは、**この文書に従うこと**。人は同じファイルを VS Code の
DocPresenter で開き、画面のまま編集し、HTML / PDF / PPTX に書き出す。

DocPresenter は **Git の差分がそのままレビューになる**ことを目的にしている。
したがって最も大事な規則は次の 1 つである。

> **頼まれたことに必要な行だけを変える。** 並べ替え・整形し直し・番号の振り直しをしない。
> 1 行の修正は 1 行の差分になっていなければならない。

---

## 1. フォルダの決まり

```
docs/
  <文書名>.md            文書の本文。frontmatter に output: を持つものが書き出しの対象
  <文書名>/              その文書だけが使う図・表・取り込み（例: login-flow.dgm）
    revision.md          その文書の改訂履歴
  assets/                画面キャプチャなどの画像
shared/                  複数の文書から引く図・表（用語集・全体構成図など）
.docpresenter/           この仕様書と、図・表の形式の仕様（spec/）
out/                     書き出しの成果物。Git に入れない
```

- **`docs/<文書名>/` はその文書専用**である。別の文書から引いてはいけない。
  2 つ以上の文書で使うものは `shared/` に置く。
- **改訂履歴は共有しない。** 文書ごとに `docs/<文書名>/revision.md` を持つ。
- 1 つのフォルダに文書が何本あってもよい。文書名は英小文字・数字・`-` で付ける（`auth-design`）。
- 新しい図や表のファイル名も同じく英小文字・数字・`-`。中身を表す名前にする（`login-flow.dgm`）。
- パスはすべて**そのファイルからの相対**で書く（`docs/a.md` から `shared/x.dgm` は `../shared/x.dgm`）。

## 2. 文書（`.md`）

素の Markdown に、次の 4 つだけを足した形式である。

1. `@import "パス" {属性}` — 図・表・別の Markdown を取り込む行
2. 見出しの `{#sec-…}` — 見出しに付けるラベル
3. 本文の `@fig-…` などの参照 — 番号に置き換わる
4. 単独の `---` — シート（画面・スライドの 1 枚）の区切り

### 2.1 frontmatter

```yaml
---
document: SD-AUTH-001     # 文書番号
title: 認証機能 設計書
version: 1.0              # 版。改訂履歴の版と揃える
status: draft             # draft / review / approved など
author: 設計チーム
updated: 2026-10-06       # 最後に内容を変えた日
theme: default
output: [html, pdf]       # 書き出す形式（html / pdf / pptx）。無い文書は書き出しの対象にならない
---
```

- 表紙は frontmatter から**生成される**。本文に文書番号や版を書き写さない。
- `contents: true / false`、`figures: true / false` で目次・図表目次を出す／出さないを決められる
  （書かなければ項目数で自動）。
- 内容を変えたら `updated` を更新する。版を上げるかどうかは人が決める。勝手に上げない。

### 2.2 見出しとラベル

```markdown
# 認証機能 設計書            ← 文書の題。1 つだけ。最初に置く

## 概要 {#sec-overview}
### 目的 {#sec-purpose}
```

- 章番号は**自動で付く**。見出しに「1.」「3.2」などを手で書かない。
- 参照される見出しには `{#sec-英小文字-}` を付ける。一度付けたラベルは変えない（参照が壊れる）。

### 2.3 シートの区切り `---`

```markdown
本文の最後の行。

---

## 次の章 {#sec-next}
```

- `---` だけの行はシート（画面の 1 枚・スライドの 1 枚）の区切りである。
- **`---` の前の行は必ず空行**にする（さもないと Markdown の見出しと区別できず、エラーになる）。
- 大きな章ごとに 1 枚、くらいの粒度で区切る。

### 2.4 図・表の取り込み `@import`

**図や表を本文に直接書かない。** ファイルにして 1 行で取り込む。

```markdown
ログイン時の画面遷移を @fig-login-flow に示す。

@import "auth-design/login-flow.dgm" {#fig-login-flow caption="ログイン画面遷移"}
```

| 属性 | 意味 |
|---|---|
| `#fig-…` / `#tbl-…` | ラベル。図は `fig-`、表は `tbl-` |
| `caption="…"` | 図表の題。番号（「図 3」）は自動で前に付く |
| `rows="範囲名"` | 表の一部だけを出す。範囲は `.table` の `range {}` に名前で定義する |
| `page="landscape"` | 横向きのページに送る（列の多い表など） |
| `width="55%"` / `align="center"` | 画像・図の幅と寄せ |
| `view="diagram" / "code" / "both"` | Mermaid を図で出すか、コードで出すか、両方か |

取り込めるもの:

| 拡張子 | 種類 |
|---|---|
| `.dgm` | DocPresenter の図。**基本はこれで描く**（PowerPoint でも図形として編集できる） |
| `.table` | DocPresenter の表。結合セル・名前付き範囲を持てる |
| `.mmd` | Mermaid（シーケンス図など、`.dgm` に無いもの） |
| `.png` `.jpg` `.gif` `.svg` | 画像（`assets/` に置く） |
| `.csv` | 表 |
| `.md` | 別の Markdown（改訂履歴など）。中身がその位置に入る |

- 知らない属性は**エラーとして報告される**。上の表に無い属性を作らない。
- 小さい表（数行・結合なし）は Markdown の表をそのまま本文に書いてもよい。
  番号を付けて参照したい表、結合のある表、共有する表は `.table` にする。

### 2.5 参照

```markdown
構成を @fig-architecture に示す。用語は @tbl-glossary を参照のこと。詳細は @sec-login で述べる。
```

- `@fig-…` は「図 3」、`@tbl-…` は「表 2」、`@sec-…` は章番号に置き換わる。
- **番号を手で書かない。**「図 3.1 に示す」と書くと、図が 1 つ増えた瞬間に全部ずれる。
- ラベルの接頭辞は `fig` `tbl` `sec` `req`（要件）`des`（設計）`tst`（試験）のどれか。
- 同じ文書の中でラベルは重複してはならない。共有の図表を取り込むときも、文書ごとにラベルを付ける。
- コード（`` `…` ``）の中の `@` は参照として扱われない。

### 2.6 コードと Mermaid

- コードブロックは開きの行に言語名を書く（` ```sql `、` ```typescript `）。色が付く。
- ` ```mermaid ` はその場で図になる。長いものは `.mmd` にして `@import` する。
- コードブロックの中では `---` も `#` もただの文字である。

## 3. 図（`.dgm`）

詳細は [spec/dgm.md](spec/dgm.md)。よく使う形だけ挙げる。

```
flow {
  start ([開始])
  input [/ID とパスワードを入力/]
  check {認証に成功？}
  home [ホーム画面]
  locked [ロック画面]

  start --> input
  input --> check
  check --> home "はい"
  check -.-> locked "5 回失敗"
}
```

- `flow { }` は接続から位置を自動で決める。`free { }` は位置をすべて `layout { }` に書く。
- 図形の形は括弧で決まる: `[四角]` `(角丸)` `([端子])` `[(円柱)]` `((楕円))` `{ひし形}`
  `{{六角形}}` `[/入出力/]` `>注記]` `"文字だけ"`。
- 接続は `-->`（矢印）、`--`（線だけ）、`-.->`（破線の矢印）。ラベルは `"…"`。
- **id は読める名前にする**（`db-primary`、`login`）。id を変えると差分が壊れるので、既存の id は変えない。
- 位置の固定（`layout { id @ (x, y) }`）は、人が画面で動かしたものである。**消したり書き換えたりしない。**
  新しい図形には位置を書かず、自動レイアウトに任せる。
- 色は書かない。`style { }` で意味の名前（トークン）を使うか、テーマに任せる。

## 4. 表（`.table`）

詳細は [spec/table.md](spec/table.md)。

```
# 用語集

| 用語             | 分類 | 説明                               |
|------------------|------|------------------------------------|
| アクセストークン   | 認証 | API 呼び出しの認可に用いる短命の資格情報 |
| アカウントロック   | ^    | 連続認証失敗によりログインを拒否する状態  |
| DMZ              | 基盤 | 外部公開セグメント                    |

range {
  認証関連: アクセストークン..アカウントロック
}

style {
  col:用語 { width: 30% }
}
```

- 書き方は GFM の表とほぼ同じ。**`^` は上のセルとの結合**、`<` は左のセルとの結合。
- 行と列は**番号ではなく名前（最初の列・見出し行の文字）で指す**。`range {}` も `style {}` も同じ。
- 先頭の `#` 行はコメント。表の中には置けない。
- 列の幅を揃えるための空白はあってもなくてもよい。**既存の表の空白を揃え直さない**（全行が差分になる）。

## 5. ラベル・セルの中の書式

詳細は [spec/inline-text.md](spec/inline-text.md)。`**太字**`、`*斜体*`、`` `コード` ``、
`[文字]{color=#c62828}`（色）。

## 6. エージェントへの約束事

1. **変更は最小に。** 頼まれていない行の空白・並び・言い回しを変えない。
2. **番号を書かない。** 章・図・表の番号はすべて自動。参照は必ず `@ラベル` で。
3. **図は `.dgm`、表は `.table`** にして `docs/<文書名>/` に置き、`@import` で取り込む。
   複数の文書で使うものだけ `shared/` に置く。
4. **既存のラベル・id・位置の固定を変えない。** 名前を変えるときは、参照しているすべての箇所を同時に直す。
5. **新しい文書を作るときは**、既存の文書の frontmatter を手本にし、`docs/<文書名>/revision.md` も作る。
6. 文字コードは UTF-8（BOM なし）。
7. 書いたあと、次を自分で確かめる。
   - 取り込んだファイルがそのパスに実在する（相対パスの `../` の数を数える）
   - 参照したラベルが文書の中（または取り込んだ文書の中）に定義されている
   - ラベルが重複していない
   - `---` の前が空行になっている
   - `@import` の属性が §2.4 の表にあるものだけである
8. 書き出し（HTML / PDF / PPTX）と画面での見た目の確認は、人が VS Code の DocPresenter で行う。
   `out/` の成果物を手で編集しない。
