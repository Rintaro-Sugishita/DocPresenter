# 検証結果 — 日本語テキストが選択可能な PDF を出せるか

実施: 2026-09-21 / 対象: [PDF 生成エンジン §7](../../design/pdf-engine.md) の最優先実測項目
環境: Node 22.22 / pdf-lib ＋ @pdf-lib/fontkit / IPAゴシック・Noto Sans CJK JP

## 結論

**出せる。方式は成立する。** 最大リスクとしていた ToUnicode CMap の問題は確認されなかった。

ただし**フォントの扱いに罠が 1 つある**。**pdf-lib のサブセット機能は CFF 系フォント（Noto Sans CJK など）を壊す**ため、
**サブセット化は自前で行う**必要がある（§フォント選定）。

## 検証方法

pdf-lib で日本語を書いた PDF を生成し、**実際の PDF ビューアのエンジン 2 種**でテキストを抽出した。
抽出できるということは、顧客が PDF 上でその文字を選択・ハイライトできるということである。

| 検証器 | 実体 |
|---|---|
| **PDFium** | **Chrome / Edge の PDF 表示エンジン** |
| **pdf.js** | **Firefox の PDF 表示エンジン** |

## 結果

| # | 検証項目 | 結果 |
|:--:|---|---|
| 1 | 日本語テキストの抽出（ひらがな・カタカナ・漢字・全角英数・丸数字・記号） | **○ PDFium / pdf.js の両方で完全一致** |
| 2 | 文字列検索 | **○** `アクセストークン` を位置付きで発見 |
| 3 | サブセット埋め込み | **○ 4,233.9 KB → 29.3 KB（約 1/144）** |
| 4 | 環境依存文字（`髙` `﨑` `彅`） | **○ 抽出・描画とも正常** |
| 5 | サロゲートペア（BMP 外、`𠮷` U+20BB7） | **○ フォントに字があれば正しく扱える**（§検証3） |
| 6 | 欠字の事前検出 | **○ 書き出し前に検出できる**（§検証4） |
| 7 | 文字単位の矩形取得 | **○ 描画指定と一致**（§検証5） |
| 8 | 描画品質（豆腐の有無） | **○ 欠字以外は正常**（`out-subset.png`） |

## 個別の検証

### 検証3 — サロゲートペアはフォントの問題だった

初回、`𠮷野`（U+20BB7）だけが抽出されなかった。原因を切り分けたところ、
**IPAゴシックがこの字を持っていない**ことが判明した（`fontTools` の cmap を確認）。

フォントを加工して U+20BB7 に字を割り当てて再試行したところ、**抽出は完全に成功した**。

```
'髙﨑・𠮷野・彅（環境依存文字）'   → OK
'𠮷野家とサロゲートペア'          → OK
```

**pdf-lib の ToUnicode は BMP 外の符号位置を正しく扱える。** 符号化の問題ではない。

### 検証4 — 欠字は「描画は豆腐、抽出は消滅」

フォントが持たない字の挙動は非対称だった。

| | 挙動 |
|---|---|
| 描画 | **.notdef の箱（豆腐）として見える** → 人間は気づく |
| テキスト抽出 | **文字ごと消える** → 検索・コピー・**注釈のアンカー**から失われる |

設計書で人名などが静かに欠けるのは看過できない。ただし **`fontkit` の
`hasGlyphForCodePoint()` で書き出し前に検出できる**ことを確認した。

```
検査文字列: 髙﨑・𠮷野・彅（環境依存文字）ｱ㈱㋿🙂
欠字      : 𠮷 ㋿ 🙂
```

`㋿`（令和の合字）や絵文字も同様に検出される。

### 検証5 — 注釈アンカーの往復が成立する見込み

PDFium から**文字単位の矩形**を取得でき、描画時の指定と一致した。

```
"アクセストークン" の文字 index = 65
  [65] 'ア' 矩形 = (61.6, 695.7, 70.8, 704.7)
  [66] 'ク' 矩形 = (73.8, 695.6, 81.7, 705.6)
  描画時の指定: x=60, y=696
```

顧客がハイライト注釈を付けると、その矩形が記録される。**こちらは各テキスト実行体をどの座標に
置いたかを知っている**ため、矩形からソースのバイト範囲に戻せる。[レビューモデル](../../design/review-model.md)の
PDF 経路が成立する見込みが立った。

## フォント選定 — Noto Sans CJK JP ＋ 自前サブセット

### 字種カバー範囲

| フォント | cmap 登録字数 |
|---|---|
| IPAゴシック | 11,462 |
| **Noto Sans CJK JP** | **44,810** |

| 文字 | 内容 | IPAゴシック | Noto Sans CJK JP |
|---|---|:--:|:--:|
| `𠮷` U+20BB7 | CJK 拡張 B・人名（𠮷野） | ✗ | **○** |
| `𠮟` U+20B9F | CJK 拡張 B・叱の正字 | — | **○** |
| `𩸽` U+29E3D | CJK 拡張 B・ほっけ | — | **○** |
| `髙` `﨑` `彅` | 環境依存文字 | ○ | ○ |
| `俱` `剝` | JIS 第 3 水準 | — | **○** |
| `㋿` U+32FF | 令和の合字 | ✗ | **○** |
| `𡈽` U+211BD | CJK 拡張 B・土の異体字 | ✗ | **✗** |
| 絵文字 | — | ✗ | ✗ |

ライセンスは **SIL OFL 1.1** で、埋め込み・再配布とも可能。**Noto Sans CJK JP を採用する。**

### 罠 — pdf-lib のサブセットは CFF フォントを壊す

Noto Sans CJK は **CFF ベース**、IPAゴシックは **TrueType ベース**である。この違いで挙動が分かれた。

| 埋め込み方 | ファイルサイズ | テキスト抽出 | **描画** |
|---|---|:--:|:--:|
| `subset: true` | 67.3 KB | **○ 完全一致** | **✗ 日本語が 1 文字も描かれない** |
| `subset: false` | 13,549 KB | ○ | ○ |
| **事前に自前サブセット ＋ `subset: false`** | **29.1 KB** | **○** | **○** |

**この壊れ方は危険である。** テキスト抽出は完全に成功するため、**自動テストが通ってしまう**。
グリフが 1 つも描かれない PDF を「検証済み」として出荷しうる。

> **PDF の検証は、テキスト抽出だけでなく描画も確認しなければならない。**

### 対処 — サブセット化は自前で行う

`fontTools` で事前にサブセット化し、`subset: false` で丸ごと埋め込むと**描画・抽出とも完全**になり、
サイズも 13.5 MB → **29.1 KB** に収まった（使用 74 字）。

TypeScript 実装では **harfbuzzjs（`hb-subset`、WASM）** が同等であり、CFF を正しく扱える。
pdf-lib 内蔵のサブセッタは使わない。

### 非 BMP 文字の検索

`𠮷` `𩸽` などの非 BMP 文字は、**抽出と選択はできるが PDFium の検索 API では一致しない**
（BMP 文字は一致する）。抽出テキストには正しく含まれているため**生成した PDF の欠陥ではなく、
ビューア側の挙動**である。顧客が Chrome で拡張漢字を検索した場合に引っかからない可能性がある。

## 残る課題

1. ~~フォント選定~~ → **決定: Noto Sans CJK JP（SIL OFL）＋ 自前サブセット**
2. **欠字検出をビルドに組み込む** — 検出できることは確認した。**警告ではなくビルド失敗**とすべきか要判断
3. **描画の検証を CI に入れる** — 上記の罠は描画を見ないと検出できない
4. **本検証はテキストを手で配置した。** 実際のパイプラインでは
   [ブラウザのレイアウト結果を読んで配置する](../../design/pdf-engine.md)。**行分割・禁則の品質と、
   レイアウト結果の読み取りは別途検証が要る**（[未確定 A-5](../../design/open-issues.md) の実測項目 2・3）

## 再現手順

```bash
npm install
node generate.mjs        # out-subset.pdf / out-full.pdf を生成
python3 verify.py out-subset.pdf out-full.pdf
node verify-pdfjs.mjs out-subset.pdf
node check-coverage.mjs  # 欠字検出
python3 patch-font.py && node generate-ext.mjs   # サロゲートペアの切り分け

# フォント選定
apt-get install -y fonts-noto-cjk
python3 extract-noto.py    # ttc から JP フェイスを取り出す
node generate-noto.mjs     # subset:true / false の比較（true は描画が壊れる）
python3 presubset.py && node generate-presub.mjs   # 自前サブセット ＋ 丸ごと埋め込み
```
